## Почему этот список работает, а собранные из /32 — нет

Большинство публичных списков — это снимок DNS: сотни адресов `/32`, снятых
однажды. Через неделю CDN переезжает, и половина списка мертва.

Здесь другой конвейер:

1. **Ручной каталог сервисов** ([`data/services/`](data/services)) — 60 сервисов,
   разбитых по категориям, с доменами и заметками. Мусор «для объёма» не
   добавляется.
2. Домены резолвятся, IP пробиваются через **Team Cymru bulk whois** → получаем
   не адрес, а **анонсируемый BGP-префикс** и ASN владельца.
3. Префикс принимается, только если IP числится за RU **или** имя AS
   заканчивается на `, RU`, либо ASN есть в белом списке анти-DDoS (Qrator,
   StormWall, DDoS-Guard, Servicepipe). Глобальные CDN и облака отсекаются.
4. Для контентных ASN (VK, Яндекс, WB, Ozon, Avito, Сбер, Т-Банк, IVI,
   Госуслуги, RSNET) префиксы **расширяются через RIPEstat announced-prefixes** —
   так в список попадают адреса, которых сейчас нет в DNS. ASN операторов связи
   никогда не расширяются: иначе мимо VPN уедет половина Ростелекома.
5. **Внешние списки** российских сетей подмешиваются как кандидаты и проходят
   тот же фильтр — подробно ниже.
6. Сети схлопываются, всё, что шире `/12`, отбрасывается; итог — 1 641 472
   адреса, а не десятки миллионов.
7. Сайты за Cloudflare остаются **только доменами** — сеть Cloudflare в direct
   отправлять нельзя.

Домены в списке нужны не «на всякий случай»: Amnezia резолвит их сама при
импорте, и они переживают ротацию адресов, которую `/32` не переживает.

## Внешние списки — как кандидаты, а не как истина

Публичных репозиториев с «российскими IP» много, и соблазн слить их к себе
понятен. Проблема в цене ошибки: один зарубежный CIDR в direct уводит трафик
мимо VPN с домашнего адреса, причём молча — пользователь ничего не заметит.

Замер на живых данных: в белом списке мобильных операторов 30 228 сетей, из них
**22 579 не российские** — США, Британия, Турция, Германия. Слить как есть
означало бы отправить четверть чужого трафика напрямую.

Поэтому [`tools/import_external.py`](tools/import_external.py) берёт чужие
данные только как кандидатов и проверяет каждую сеть по таблице IP→ASN
([iptoasn.com](https://iptoasn.com/), один файл, без ключей и лимитов):

- оба конца сети должны лежать в **одном ASN** — сеть на стыке двух владельцев
  целиком в direct не поедет;
- ASN не из deny-листа глобальных CDN, страна — RU;
- **ASN уже должен обслуживать сервис каталога** — внешние списки углубляют
  покрытие того, что мы ведём, а не расширяют его вслепую;
- и отдельно отсекаются **операторы связи**, по размеру анонсируемого
  пространства: контентные площадки каталога держат от 256 адресов до 219 648,
  операторы начинаются с 280 576 и доходят до 9 169 152 у Ростелекома. Порог
  проведён по этому разрыву, ручной список не нужен. Без такой отсечки во
  внешний слой приезжал миллион адресов Ростелекома — ровно то, ради чего ASN
  операторов никогда не разворачиваются целиком;
- принятая сеть заменяется **анонсируемым префиксом**, внутри которого лежит:
  190 сетей вместо 1465 фрагментов `/24`, и покрытие переживает ротацию адресов.

Домены из внешних источников в сборку не идут вообще — список доменов
курируется руками. Те, которых нет в каталоге, попадают в
[`data/external-report.md`](data/external-report.md) вместе с разбором, что и
почему отсеялось; там же список российских ASN, которых в каталоге нет — готовый
материал для следующего пополнения.

Источники перечислены в
[`config/external-sources.json`](config/external-sources.json), результат
проверки — в [`data/external.json`](data/external.json). Прогнать вручную:

```bash
python3 tools/import_external.py --dry-run
```

## Windows — полностью автоматически

Требования: Windows 10/11, AmneziaVPN 5.x, PowerShell 5.1 (встроенный) или 7.x.
Установщик запускается **от имени администратора** — иначе задача не сможет
перезапускать службу `AmneziaVPN-service`.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File windows\install.ps1
```

Installer прогоняет self-test и dry-run, копирует updater в
`%LOCALAPPDATA%\AmneziaRouteSync` и регистрирует Scheduled Task: обновление при
входе в Windows и **каждые 6 часов**. Updater скачивает опубликованный список,
запоминает состояние подключения, закрывает AmneziaVPN, меняет ровно три
значения реестра в `HKCU\Software\AmneziaVPN.ORG\AmneziaVPN\Conf`
(`ExceptSites`, `routeMode`, `sitesSplitTunnelingEnabled`), проверяет запись и
возвращает приложение с туннелем в прежнее состояние. `Servers.*`, конфиги и
ключи не трогаются. Незавершённая транзакция журналируется и откатывается при
следующем запуске.

**Почему больше не нужна перезагрузка Windows.** Демон `AmneziaVPN-service` не
разбирает туннель, когда GUI просто закрывают: маршруты старого списка остаются
в таблице маршрутизации, и новый список «не работает» до ребута. Updater
перезапускает службу сам и поднимает соединение через
`AmneziaVPN.exe --connect <index>` — ровно то, что раньше делала перезагрузка.

Лёгкий список вместо полного, свой источник, проверка без записи:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File windows\install.ps1 -Lite
powershell -NoProfile -ExecutionPolicy Bypass -File windows\update-amnezia-routes.ps1 -Source .\dist\amnezia-ru-direct.json
powershell -NoProfile -ExecutionPolicy Bypass -File windows\update-amnezia-routes.ps1 -DryRun
```

Проверка состояния и удаление:

```powershell
Get-Content "$env:LOCALAPPDATA\AmneziaRouteSync\status.json"
powershell -NoProfile -ExecutionPolicy Bypass -File windows\uninstall.ps1
```

Ручные записи, добавленные в Amnezia самостоятельно, сохраняются — скрипт
заменяет только те, которыми управлял сам. Снести всё и оставить только наш
список: флаг `-ReplaceAll`.

### Как обновиться до свежей сборки вручную

Задача сама сходит за списком при входе в Windows и каждые 6 часов, так что
обычно делать ничего не нужно. Ниже — что ввести, если новый список нужен прямо
сейчас или после `git pull`.

**Откройте PowerShell от имени администратора**: `Win` → наберите `powershell` →
правой кнопкой на «Windows PowerShell» → **«Запуск от имени администратора»**.
Без прав администратора задача не сможет перезапускать службу
`AmneziaVPN-service`, и список применится только после ребута.

Дальше — команды по порядку, каждая отдельной строкой. Путь к репозиторию
поправьте под свой, если клонировали не в домашний каталог.

Забрать свежую сборку и код:

```powershell
cd "$env:USERPROFILE\amnezia-split-route-sync"; git pull
```

Переустановить updater — обязательный шаг после `git pull`: задача запускает
копию из `%LOCALAPPDATA%`, а не файл из репозитория, и без этого шага правки
кода не подхватятся:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File windows\install.ps1
```

Применить список:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA\AmneziaRouteSync\update-amnezia-routes.ps1"
```

Проверить, что применилось:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA\AmneziaRouteSync\update-amnezia-routes.ps1" -Status
```

Что должно быть в выводе `-Status`:

```
Записей в Conf\ExceptSites: 1609
routeMode: 2 (нужно 2)
sitesSplitTunnelingEnabled: true (нужно true)
Ключей-сетей: 621, ключей-доменов: 988
Служба демона: AmneziaVPN-service = Running
маршрут до gosuslugi.ru: префикс 213.59.252.0/22, шлюз 192.168.1.1, интерфейс Ethernet
```

Числа должны совпадать с таблицей в начале файла. Главная строка — последняя:
маршрут до Госуслуг идёт через **домашний шлюз и обычный интерфейс**, а не через
`AmneziaVPN / WireGuard Tunnel`. Значит раздельное туннелирование работает.

`AmneziaVPN уже содержит актуальные 1609 записей` вместо `AmneziaVPN обновлена` —
не ошибка: задача успела применить список сама сразу после `install.ps1`.

**Если что-то пошло не так.** `Источник не ответил за 60 секунд` — сеть или
GitHub не отвечают; updater делает три попытки сам, повторите запуск позже.
Консоль ушла в `>>` и не реагирует — в команду улетела лишняя кавычка, нажмите
`Ctrl+C`. `-ReplaceAll` нужен, только если хотите стереть свои ручные записи в
Amnezia; при обычном обновлении он не нужен.

### Если автоматизация не нужна — импорт вручную

1. Скачайте `amnezia-ru-direct.json` из [Releases](../../releases/latest).
2. Откройте AmneziaVPN → **Настройки** → **Раздельное туннелирование сайтов**.
3. Выберите режим **«Адреса из списка не должны открываться через VPN»**.
4. Нажмите `⋮` → **«Заменить список с сайтами»** → выберите скачанный JSON.
5. Переподключите VPN.

Проверка: `myip.com` должен показывать IP VPN, а `2ip.ru` — ваш домашний.

## macOS — полностью автоматически

Здесь автоматизация работает нормально: AmneziaVPN на macOS перечитывает
настройки при старте, перезагрузка не нужна.

Требования: macOS 14+, AmneziaVPN 5.x в `/Applications`, системный Python 3,
Xcode Command Line Tools.

```bash
xcode-select --install   # если Command Line Tools ещё не стоят
bash macos/install.sh
```

Что делает installer: собирает Swift-helper, прогоняет dry-run и только после
успешной проверки ставит пользовательский LaunchAgent
`io.github.amnezia-route-sync` — обновление при входе в систему и **каждые 6
часов**. Updater скачивает опубликованный список, запоминает состояние
AmneziaWG-подключения, аккуратно закрывает AmneziaVPN и `amneziawg-go`, меняет
ровно три ключа (`Conf.ExceptSites`, `Conf.routeMode`,
`Conf.sitesSplitTunnelingEnabled`), проверяет запись и возвращает приложение в
прежнее состояние. Незавершённая транзакция журналируется и откатывается при
следующем запуске. `Servers.*`, конфиги и ключи не трогаются.

**Боевой запуск идёт из установленной копии, а не из репозитория.** Настройки
Amnezia меняет не сам Python-скрипт, а маленький Swift-хелпер
`set-amnezia-routes`: он компилируется при установке и кладётся рядом со
скриптом в `~/Library/Application Support/AmneziaRouteSync/`. В репозитории
лежат только исходники, поэтому запуск оттуда обрывается на
`ОШИБКА: не найден исполняемый helper`. Из репозитория работает `--dry-run`:
он ничего не пишет и хелпер ему не нужен.

Проверить список без единой записи в настройки — можно откуда угодно:

```bash
python3 macos/update_amnezia_routes.py --dry-run
```

Применить, лёгкий список вместо полного, свой источник:

```bash
python3 "${HOME}/Library/Application Support/AmneziaRouteSync/update_amnezia_routes.py" --lite
```

```bash
python3 "${HOME}/Library/Application Support/AmneziaRouteSync/update_amnezia_routes.py" --source ./dist/amnezia-ru-direct.json
```

Проверка состояния:

```bash
launchctl print "gui/${UID}/io.github.amnezia-route-sync"
```

```bash
cat "${HOME}/Library/Application Support/AmneziaRouteSync/status.json"
```

Ручные записи, добавленные в Amnezia самостоятельно, сохраняются — скрипт
заменяет только те, которыми управлял сам.

Если в Amnezia лежит старый сторонний список, он тоже считается «ручным» и
переживёт обновление. Снести всё и оставить только наш список:

```bash
python3 "${HOME}/Library/Application Support/AmneziaRouteSync/update_amnezia_routes.py" --replace-all
```

### Как обновиться до свежей сборки вручную

Агент сам ходит за списком каждые 6 часов, так что обычно делать ничего не
нужно. Ниже — что ввести, если новый список нужен прямо сейчас или после
`git pull`. Права администратора не нужны: агент работает от вашего пользователя.

Забрать свежую сборку и код:

```bash
cd ~/amnezia-split-route-sync && git pull
```

Переустановить — обязательный шаг после `git pull`: агент запускает копию из
`~/Library/Application Support/AmneziaRouteSync/`, а не файл из репозитория, и
заодно пересобирается Swift-хелпер:

```bash

```

Применить список:

```bash
python3 "${HOME}/Library/Application Support/AmneziaRouteSync/update_amnezia_routes.py"
```

Проверить, что применилось:

```bash
python3 -c "import json,pathlib;d=json.loads((pathlib.Path.home()/'Library/Application Support/AmneziaRouteSync/status.json').read_text());print(d['entry_count'],'записей,',d['cidr_count'],'сетей,',d['domain_count'],'доменов')"
```

Числа должны совпадать с таблицей в начале файла. Убедиться, что маршрутизация
живая: при включённом VPN откройте [yandex.ru/internet](https://yandex.ru/internet) —
там должен быть ваш домашний российский IP, а на зарубежном сайте вроде
`myip.com` — адрес VPN-сервера.

`AmneziaVPN уже содержит актуальные записи` вместо `AmneziaVPN обновлена` — не
ошибка: агент успел применить список сам.

   «Файлы»). Можно передать через AirDrop, облако или мессенджер.
2. AmneziaVPN → **Настройки** → **Раздельное туннелирование сайтов**.
3. Режим **«Адреса из списка не должны открываться через VPN»** → `⋮` →
   **«Заменить список с сайтами»** → выберите файл.
4. **Переподключите VPN** — без этого маршруты не встанут.

Проверка: откройте [yandex.ru/internet](https://yandex.ru/internet) — должен
показать домашний российский IP.

**Если IP всё ещё зарубежный** — почти наверняка у вас Amnezia Free: там
раздельное туннелирование по IP отключено, и никакой список не поможет.
Нужен AmneziaVPN со своим сервером или клиент с собственным роутингом
(Happ и подобные).

## Linux

Ручной импорт через интерфейс Amnezia. Либо возьмите `ru-direct-ipv4.txt` и
`ru-direct-domains.txt` и скормите их своему роутингу напрямую.

## Клиент не умеет split tunneling — правим AllowedIPs

Самый надёжный способ, работает где угодно: раздельное туннелирование делается
не функцией клиента, а самим конфигом туннеля.

В `wg-allowed-ips.txt` лежит готовая строка из 3743 префиксов — весь IPv4 минус
российские сети и минус приватные диапазоны. Замените ей `AllowedIPs` в секции
`[Peer]` конфига WireGuard или AmneziaWG:

```ini
[Peer]
PublicKey = ...
Endpoint = ...
AllowedIPs = 1.0.0.0/8, 2.0.0.0/7, 4.0.0.0/8, 5.0.0.0/13, ...
```

Туннель просто не забирает российские адреса — они уходят напрямую мимо VPN.
Клиенту для этого не нужно уметь ничего: ни split tunneling, ни домены, ни
платную подписку. Работает в родных приложениях WireGuard и AmneziaWG на iOS,
Android, десктопах и роутерах.

Минус ровно один: покрытие только по IP. Сайты за Cloudflare, которые в полном
списке держатся доменами, сюда не попадают.

## Happ, Xray, роутеры

`happ-ru-direct.json` — готовый фрагмент профиля Happ:

```json
{ "DirectSites": ["domain:vk.com", "..."], "DirectIp": ["87.240.128.0/18", "..."] }
```

Вставляется в свой routing-профиль Happ либо конвертируется в
`geosite`/`geoip`-правила Xray. `ru-direct-domains.txt` подходит для AdGuard
Home, dnsmasq-ipset и OpenWrt.

## Свои домены и сети

Каталог открыт: [`data/services/`](data/services). Каждый файл — категория,
внутри массив сервисов:

```json
{
  "id": "my-service",
  "title": "Мой сервис",
  "tier": "core",
  "domains": ["example.ru", "api.example.ru"],
  "cidrs": ["203.0.113.0/24"],
  "notes": "зачем добавлено"
}
```

`tier: "core"` — попадает и в полный список, и в lite. `tier: "extended"` —
только в полный. После правки:

```bash
python3 tools/catalog.py           # валидация каталога
python3 tools/import_external.py   # перепроверить внешние списки (сеть, ~1 минута)
python3 tools/refresh_prefixes.py  # обновить BGP-снимок (сеть, ~2-3 минуты)
python3 tools/build_ru_direct.py   # пересобрать dist/
```

Порядок важен: импорт сверяется с набором ASN из прошлого снапшота, а
`refresh_prefixes.py` уже подмешивает его результат. Собрать список без внешнего
слоя — `python3 tools/refresh_prefixes.py --no-external`.

Личный сборочный прогон с приватными сервисами, которые не должны попасть в
публичный репозиторий:

```bash
python3 tools/build_ru_direct.py --personal ~/private-services.json --output-dir ~/Downloads/ru-direct
```

## Приватность и безопасность

- В репозитории нет VPN-конфигураций, ключей, паролей, UUID и адресов серверов.
- IP собственного VPN-сервера, который **никогда** не должен уехать в direct,
  кладётся в `config/protected-ips.json` — файл в `.gitignore`, установленная
  копия получает mode `600`:

  ```bash
  cp config/protected-ips.example.json config/protected-ips.json
  ```

  Любая сеть, покрывающая защищённый IP, — фатальная ошибка обновления.
- Списки скачиваются только по HTTPS с проверкой сертификата, лимитом размера и
  таймаутом. Отклоняется всё, что шире `/12`, а также аномальный рост или
  обвал числа записей.
- macOS-часть работает от пользователя: user LaunchAgent, никакого root.
- `python3 tools/privacy_scan.py` проверяет, что в репозиторий не просочились
  приватные файлы и байткод.

Импорт — это намеренный split tunnel: сайты из списка видят ваш реальный IP.
Не добавляйте туда сервисы, которые должны оставаться внутри VPN.

## FAQ

### Почему Госуслуги/Сбер просят капчу или не пускают через VPN?

Российские сервисы блокируют зарубежные IP и хостинговые ASN. Split tunneling
возвращает им ваш домашний адрес, оставляя VPN для остального интернета.

### Не грузится VK Видео / не заливаются VK Клипы через VPN — поможет?

Да, это основной сценарий списка: домены загрузки и VK CDN идут напрямую.

### Как часто обновляется список?

Пересборка и релиз — раз в неделю по расписанию GitHub Actions, плюс вручную
после правок каталога. macOS-агент проверяет обновление каждые 6 часов.

### Список тормозит Amnezia?

Полный — 1609 записей, на современных устройствах незаметно. Если интерфейс
подлагивает, берите lite (893 записи): внешний слой сетей в него не входит
специально.

### Чем это отличается от готовых списков на 5000 доменов?

Там объём ради объёма: мёртвые домены, зарубежные сайты, `/32`-снимки, которые
протухают. Здесь — проверенные сервисы, BGP-префиксы вместо снимков DNS и
отсечка глобальных CDN. Чужие списки используются, но как кандидаты: каждая сеть
из них проходит проверку по ASN, и до сборки доходит меньше процента записей.

### Работает ли с AmneziaWG?

Да. AmneziaWG — протокол внутри AmneziaVPN 5.x; split tunneling настраивается
там же. Отдельный native-клиент AmneziaWG не редактируется.

### IPv6?

Нет. AmneziaVPN маршрутизирует по IPv4-списку; IPv6 проект не настраивает.

## Удаление (macOS)

Сначала очистите или замените список в самой AmneziaVPN — остановка агента уже
импортированные маршруты не удаляет.

```bash
bash macos/uninstall.sh
```

## Разработка

```bash
python3 tools/privacy_scan.py
python3 tools/catalog.py
python3 tools/build_ru_direct.py --dry-run
python3 -m py_compile macos/update_amnezia_routes.py tools/*.py
bash -n macos/install.sh macos/uninstall.sh
```

## Ограничение ответственности

Проект не связан с Amnezia и не является официальным компонентом AmneziaVPN.
Маршруты и инфраструктура сервисов меняются; проверяйте результат на своих
устройствах. Используйте только там, где это разрешено правилами сервисов и
законом вашей юрисдикции.
